# 项目目标与里程碑

## 目标与维护方式

将原 Keil 机器人固件逐步迁移到 **CubeMX + CubeIDE + HAL**，每一步保持可构建、可验证、可回退。

- 按用户要求保留 `firmware/CornerStone_LED` 作为独立点灯测试，复制 `firmware/CornerStone_Robot` 作为后续机器人重构起点；后续增量迁移默认在 Robot 内进行。
- 两个工程分别从各自的 `STM32CubeIDE` 目录导入，独立构建；根目录旧 Keil 工程和机器人代码仅供参考，尚未纳入新构建。
- 本文件维护阶段目标、状态、决策与证据入口，不复制操作手册或完整测试日志。规划下一阶段、确认迁移范围或更新进度时读取；普通局部修改无需默认通读。
- 仅在范围获批、验收证据变化或阶段关闭时更新。候选方向不代表已批准任务；临时步骤与执行流水放在任务自己的 `task_plan.md` / `progress.md`。

## 已关闭：LED 最小固件

完成内容：

- 建立芯片、时钟、GPIO 配置及 CubeMX 生成代码基线。
- 建立 CubeIDE 编译与 CMSIS-DAP/OpenOCD 下载链路。
- 将 LED 应用与生成代码分离，验证再生成保留应用文件及调用。
- 当前行为为 PG1–PG8 低电平点亮，每步 1 秒、每轮 8 秒。

验收边界：

- 已有 CubeIDE 构建、下载校验与复位、时钟/GPIO 寄存器检查记录，但它们对应的固件修订不同，不得合并为同一镜像的全量实测。
- 用户确认过 500 ms 版本的流水灯行为；后续 1000 ms 版本有用户报告的构建、ELF 延时检查及烧录校验记录。
- 用户明确关闭本阶段。旧记录中的物理复测/完整断电启动待办是历史边界，不自动重新激活，也不补写为已实测通过。
- Windows 构建和硬件验收仍未完成。

证据：[固件说明与关闭记录](../firmware/README.md)、[详细验证记录](../firmware/docs/validation.md)。

## 配套：硬件资料

已归档 RoboMaster A 型资料及 STM32F427 RM0090，建立可追溯摘要、引脚表和完整性哈希。

- 资料证明的是文档标注和连接关系，不是板上频率测量、通断测试或器件实物确认。
- IMU 型号、磁力计地址及 USER UART 电源域等来源冲突仍未裁决；迁移相关模块前必须查阅并解决适用问题。
- 不因资料已归档，就认定所有外设已配置或驱动已验证。

入口：[硬件资料与已知冲突](hardware/README.md)。

## 配套：CubeIDE 下载与调试

现有入口的验证状态不同：

- **Flash and Debug**：用户确认过先前绝对路径 macOS 配置可用；共享 PATH 版本已有静态配置检查及无硬件 GDB/OpenOCD 管道冒烟测试，仍需在实际 CubeIDE 启动环境中确认。不能据此宣称该修订的下载、断点、单步或 Windows 行为已通过。
- **Flash and Run**：入口与配置说明已提供，IDE/硬件验收仍待完成。它只下载已有 ELF，不自动保证构建成功或产物新鲜度。
- Windows/Linux 运行验证未完成；不将跨平台配置语法等同于跨平台运行成功。

操作与最新边界：[固件说明](../firmware/README.md)、[调试器配置指南](../firmware/docs/debugger-setup.md)。这些验证事项不授权自动连接或烧录硬件。

## 下一阶段：范围待确定

已确定的方向是增量迁移，而不是再次整体重建：

1. 选定一个可独立验证的功能，明确硬件连接、旧代码依赖和验收标准。
2. 在 `.ioc` 中配置所需外设，适配该功能的驱动/应用，完成生成、构建和适当的板上验证。
3. 随实际依赖逐步建立应用、设备和板级适配边界；优先复用不依赖硬件的算法与协议逻辑。
4. 仅在需要并获批时引入 RTOS，届时单独确定任务划分、阻塞行为、中断及共享资源管理。

UART、CAN、SPI、传感器或电机等只是候选方向，**尚未选择优先级或批准实施范围**。已按用户要求保留独立 LED 测试工程并建立 Robot 副本；旧目录清理和机器人功能迁移不在本次工程分离范围内。
