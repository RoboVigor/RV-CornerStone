# 关节 0 PID 自动整定实施计划

状态：用户已以“Implement the plan”授权软件实施及离线验证。本文不构成当前运行硬件或烧录的授权；当前使用与验证边界见 [交付手册](gimbal-pid-tuning-runbook.md)。

背景事实见 [gimbal-pid-auto-tuning.md](gimbal-pid-auto-tuning.md)。本文记录五轮需求澄清后的方案；具体参数、机械边界和性能阈值不得从示例推断。

## 1. 已确认的目标与范围

- 对象：关节 0 的双 GM6020 电机组（0x205、0x206），位置 PD + 速度 PI，motor0 作为闭环反馈，输出保持 50/50 分配。
- 第一版：固定姿态/负载的单工况自动整定；不做多工况增益调度或持续在线自适应。
- 优先级：先限制超调、回弹和持续震荡，再缩短稳定时间，不以首次到达目标时间作为唯一目标。
- 实验动作由程序生成，批次内允许用已验收基线自动准备起点，不要求人工逐轮拨动。
- 原始现象发生于使能状态下被手拨动/按住。积分积累是待验证假设，不能直接认定根因。相同位置误差但积分、初速度、微分历史不同，不等于相同实验。
- 原则上以自动目标响应作为优化实验；人工拨动恢复仅作可选体验验收，不由目标阶跃结果直接推断。
- 其他关节保留原控制、保持固定安全姿态，不随关节 0 测试目标运动；不可通过全局 SafetyMode 简单断力。
- 用户确认：支撑及安全行程可以承受关节 0 双机零输出和短暂惯性滑行。具体停距与边界仍须现场核实。
- 关节 0 上电/复位默认零输出，必须明确启动才能使能；普通停止、单轮正常结束和严重故障均双机零输出。
- 故障锁定，重连不恢复运动、不自动重试失败实验；人工重新授权后重新开始完整实验。
- Windows 运行 Python 和 VOFA；用户负责 Keil 烧录、现场保护与实机验收。
- 第一版为命令行 + 配置文件 + VOFA，无 GUI、无设备 Flash 参数保存。日志及最佳候选保存在 PC，候选仅 RAM 试用，验收后人工发布。

## 2. 架构与边界

```text
Windows Python CLI
 ├─ 配置/准入校验
 ├─ 实验管理器：会话、批次、起点准备、超时、中止
 ├─ BayesianOptimization：提议参数、接收完整有效实验评分
 ├─ 日志/结果报告/候选导出
 └─ 串口唯一持有者
       ↕ 带版本、序号和校验的二进制帧
STM32F427II
 ├─ 协议接收/参数事务/命令状态
 ├─ 关节0调参状态机与测试目标生成
 ├─ 双电机安全监督与零输出覆盖
 ├─ 现有实时双环控制
 └─ 有界遥测缓冲

Python → 本机 UDP JustFloat → VOFA（只读看波形）
```

- BO 不进入 1 ms 控制循环，每段实验使用固定参数。
- UART 解析、日志和优化计算不能阻塞实时控制；中断只做必要接收搬运，不执行搜索或复杂解析。
- Python 独占设备串口，VOFA 不直接打开同一串口。UDP 转发以现场 VOFA 支持为验收项，VOFA 不参与控制与保护。
- VOFA 断开不影响完整串口记录；遥测缺失超过准入阈值则本轮无效，不能悄悄计算正常评分。
- 现有 USART3_IRQHandler 走 Bridge_Receive_USART，必须显式接管/隔离调参模式，而非叠加两个接收解析器。
- 现有 Keil 工程为 mdk/infantry.uvprojx，目标 STM32F427II，uAC6=0；新文件需加入现有工程。不能将主机测试通过冒充固件编译成功。

## 3. 配置与准入

配置分层，不允许缺省安全数值后直接执行实机。

### Gate A：连接、读取、离线测试

只读设备信息/状态和模拟传输不需要运动授权。连接、重连、读取配置均不得使能电机。

### Gate B：有保护的基线试验

必须确认：
- 固件/协议版本、双电机映射、角度/速度单位、方向与零位。
- 关节 0 允许位置区间、包含滑行停距的边界余量、最大速度、输出/电流/温度约束。
- 双机反馈时效、PC心跳期限、准备/稳定/运行阶段超时。
- 其他关节的固定姿态、稳定容差、现场支撑和独立急停。
- 明确的起点/目标、小幅测试轨迹、单次时长、人工监护确认。
- 基线参数配置及状态初始化策略；仓库现有参数是待测试基线，不自动视为已知安全种子。

### Gate C：BO 自动跑批

除 Gate B 外，还必须有：
- 已通过小幅实验的基线与起点准备策略。
- 用户根据基线确认的超调上限、最终误差带、保持时长与稳定时间要求。
- 有界 PID 搜索范围（不能把单个稳定点外推成整个稳定参数盒）。
- 总候选数/总时长/单轮时长/重复次数/终止规则等实验预算。
- 评分定义版本、场景序列、随机种子、参数单位和固件版本。

无硬件保护配置不得测实机基线；无搜索范围及评分要求不得启动 BO。离线示例配置明确标记为不可用于硬件。

## 4. 协议与参数事务

以下为拟定消息职责，不表示已经存在的 API：

- HELLO / GET_STATUS / GET_CONFIG：只读版本、启动标识、状态、配置与参数版本。
- SET_SAFETY_CONFIG：只在零输出且非运行状态下设置完整试验边界，拒绝非法/缺失值；运行时禁止放宽。
- SET_BASELINE / STAGE_CANDIDATE：配置基线或暂存候选，不触发运动。
- START_BATCH / START_TRIAL：明确启动，携带新会话和实验标识，并经准入校验。
- HEARTBEAT：有独立活性语义；不能把旧重放帧或持续遥测当作授权。
- STOP：任何有效状态下均可请求关节 0 双机零输出，取消当前批次；需要收到设备状态确认，失联则靠 MCU 超时保护。
- CLEAR_FAULT：仅清除已满足恢复条件的故障，不等于使能；START 是独立动作。
- RESULT / FAULT / ACK / NACK：返回状态、参数版本、生效采样序号和拒绝/中止原因。

帧含同步、版本、消息类型、长度、会话/序号、负载及 CRC；明确字节序、字段大小、长度上限和重同步行为。禁止直接传裸 C 结构体造成填充/大小端歧义。

同一命令重试不得重复启动运动：确认超时先查询状态，仅在相同启动标识/会话内按同一序号重试；重启或重连清除原运动授权。陈旧 START 不得在 STOP 或新会话之后重新启动。

整组参数校验 finite、范围及版本后暂存，在控制周期边界统一应用；确认携带实际生效版本。禁止串口中断逐项修改正在运行的 PID。运行中不任意切换候选。

所有角度以 rad、角速度以 rad/s 表达；CLI 可以显示度，但协议与日志保留明确单位。当前离散 PID 的 i/d 采样语义保留并记录，不擅自把所有关节改成连续时间系数。

## 5. 状态机、停止与重新准备

```text
BOOT → IDLE_ZERO
IDLE_ZERO --明确授权启动--> PRECHECK
PRECHECK → PREPARE_BASELINE → SETTLE → APPLY_CANDIDATE → RUN
RUN --正常结束--> COMPLETE_ZERO
COMPLETE_ZERO --有效批次内的下一轮--> PRECHECK
COMPLETE_ZERO --批次结束--> IDLE_ZERO

任何运动状态 --普通STOP--> STOPPED_ZERO（取消批次授权）
任何相关状态 --保护/失联--> FAULT_LATCHED_ZERO（取消批次授权）
FAULT_LATCHED_ZERO --条件恢复+人工清故障--> IDLE_ZERO
```

- COMPLETE_ZERO 确实双机零输出；下一轮重新读取真实位置和速度，不假定未滑移。
- 自动准备仅在已批准批次内，采用已验收基线与限速/限加速度轨迹；当前位置越界、反馈不可信、稳定失败则拒绝运动/锁定故障。
- 候选触发保护或实验执行失败时，不使用另一组候选“救场”；先停机、记录并锁定，人工确认后才开启新实验。完整且未触发保护、仅性能评分不佳的实验可以在既定批次内继续下一轮。
- PREPARE 到 RUN 统一积分、目标与微分历史的初始化/转移策略，记录状态；避免参数切换产生不可控跳变。具体采用的状态转移算法通过离线测试与实机对照决定。
- 用户所选“回退”指保留可恢复的基线配置，不是故障时自动用基线接管继续运动。
- 关节 0 两台中任一掉线即成组处理，不允许另一台继续按双机工况驱动。在线检查的 motor0 重复读取问题必须修复。
- 零输出要覆盖最终 CAN 发送，并在许可的发送路径中明确发送零帧，不能只设 online=0 后停止发包而假定电调已停；同帧其他电机槽位保持既有控制。
- 其他关节失去既定保持条件时，中止关节0实验；不擅自让整臂失去支撑。其他关节自身异常仍由已验证的现场保护/急停方案处置，本任务不承诺整臂故障安全。

## 6. 控制算法与基线纪律

1. 先补齐必要保护和观测，不改变原 PID 计算规律，进行受保护的小幅原始基线实验；若无法安全完成，不强行补齐基线。
2. 观察位置/速度误差、速度积分项、输出饱和和反馈时效，验证积分积累、延迟等假设。
3. 在关节0范围内逐项引入抗饱和和状态切换处理；优先评估条件积分等小改动，不能直接改变所有 PID 用户的语义。
4. 不用反复 PID_Init() 代替参数更新；起点准备与评分窗口的状态策略必须可重复。
5. 保留原始基线与改进后基线的独立版本，BO 固定在一个已验收控制算法版本上运行。
6. 若证据表明位置 D 噪声、目标突变微分冲击或机械问题主导，应暂停增益搜索并定位；滤波/微分定义等额外改动需另记版本及范围，不能在搜索中偷偷改变被控系统。

## 7. 遥测、评分与 BO

### 遥测

记录 MCU 单调时间/采样序号、会话/实验编号、状态、目标位置和速度、两电机位置/速度/反馈电流/温度、位置/速度误差、PID积分项与总输出、两机实际输出指令、饱和/保护标志、参数版本、反馈年龄。关键通道优先，状态和温度可低频发送。

控制频率与遥测频率分离；根据实际帧大小和500000波特率预算降采样/分组、DMA排队与丢帧计数，禁止每个tick盲目重启未完成发送。测量真实控制周期、抖动及反馈更新率。

### 试验与指标

- 用固定的小幅双向目标变化与可重复起点建立评分窗口，准备阶段不计入跟踪评分，但失败单独记录。
- 多个起点/方向可属于同一个姿态/负载工况；保证每个候选场景相同，重复实验估计噪声，必要时穿插基线发现漂移。
- 稳定时间定义为进入误差带并持续满足保持时间的时刻；不得将首次穿越目标算作稳定。
- 性能约束优先于速度：超调超限、持续振荡不能因为到位快而胜出。可在可接受结果内优化归一化后的稳定时间、累计误差和输出变化。
- 区分完整实验性能不合格、保护中止、通信无效、准备失败和预算结束；不把中断前的部分积分误差当作完整且更优的分数。
- 首版不实现 ESBO 的截断成本推断。无效/中止试验保留原因，不注册为普通有效BO观测；保护触发锁定并停止批次。完整但性能不合格实验的约束/惩罚规则显式记录。

### 优化流程

- 固定位置环策略，先调速度 PI；速度环测试模式通过受限速度参考进行，不让位置外环掩盖结果，同时仍执行关节位置边界监督。
- 固定已验收速度环，再调位置 PD；最终用完整双环目标响应验证。
- 固定Ki=0建立基线可作为诊断对照，不预先断言其最佳。
- 基于已验收参数和小范围边界提出候选，不对整个机械系统做无约束随机初始化。
- 固定依赖版本，使用提议/注册式接口让实验管理器掌握每次真实评估，不让优化库直接无限循环控制串口。
- 输出最佳候选、置信不足说明和原始记录；独立重复验收后才能标记为可发布。搜索结束不自动加载最佳候选让电机运动。
- 保存有效观测与配置便于离线复现；实机断线/重启后不自动恢复未完成批次。

## 8. 分阶段实施与验收

### A. 协议与离线实验骨架
- 定义上述配置、消息、单位、状态、结果分类和日志格式。
- 实现Python编解码、配置校验、模拟设备和CLI骨架。
- 测试坏帧、截断、重放、乱序、重复START、超时、重连与未知版本。
- 验收：不连设备可跑模拟完整实验；无运动准入配置时拒绝硬件启动。

### B. 固件保护与双向通信
- 修复双机在线检查，增加关节0模式隔离、上电零输出和成组输出覆盖。
- 接入USART3双向协议、心跳/反馈时效检查、故障锁定与独立清除/启动。
- 实现原子参数暂存/生效及状态回读；加入Keil工程。
- 验收：离线状态测试通过；用户在Windows编译/烧录，并现场验证双机零输出及不影响其他关节。未通过前不进行候选运动实验。

### C. 遥测与单次自动实验
- 增加缓冲遥测、Python日志和VOFA UDP转发。
- 实现预检、基线准备、稳定等待、目标/受限速度测试、结束零输出。
- 验证时间戳、丢帧率、控制抖动、真实单位与两机一致性。
- 验收：用户先确认Gate B数值，再运行人工批准的小幅单轮实验，自动完成并生成完整报告；STOP、失联和单机掉线按状态机处理。

### D. 基线与控制修正
- 沿用C阶段已确认的Gate B数值，重复采集并分析原始基线。
- 根据波形逐项修正关节0抗饱和/状态切换，保留对照。
- 重新测量改进后基线，由用户确定性能阈值、搜索边界和预算。
- 验收：可重复且通过准入的基线，未通过则不接实机BO。

### E. BO 联调
- 接入BayesianOptimization提议/注册、阶段性速度PI与位置PD优化。
- 实现性能评分、预算、候选合法性检查、最优候选导出与中止分类。
- 先在模拟对象和录制数据上验证优化与评分，再现场监护下运行批准范围内的批次。
- 验收：无需逐轮手拨，自动准备并完成有效实验；故障不自动恢复；最佳结果可追溯至完整数据。

### F. 最终验收与交付
- 独立重复测试最佳候选与改进后基线，检查双向响应和全部约束。
- 用户可在批准条件下做手拨体验验收；若按住期间状态不同导致回摆，单独诊断，不混淆评分。
- 交付Windows安装/运行/烧录说明、配置模板、保护检查单、CLI、协议、日志与结果报告。
- 人工决定是否发布参数；首版不改写Flash或自动更换默认增益。

每个实施子任务进入执行后都建立可见todo；现场阶段无法由当前环境完成时保留为待验收，不报告“全部通过”。

## 9. 验证边界与停止条件

规划时仅完成源码静态核对、需求澄清和计划文档。现已进入软件实施；当前通过/失败/未运行项以任务进度和交付手册为准，不能将模拟、主机 C 测试或头文件边界语法检查称为真实 Keil 编译或硬件验证。

以下均为真实实施门槛：硬件数值配置、独立急停/支撑、Windows工具链、串口连接与VOFA UDP支持、实测基线和用户性能阈值。发现缺失必须明确报告，不擅自猜测。

如果原控制不能安全完成小幅基线、反馈不可信、协议占用冲突未解决或其他关节保持条件不成立，停止实机阶段，回到诊断/离线验证。任何进度压力不得绕过准入。

## 10. 授权与现场确认

用户已确认进入软件实施。A–F 的软件部分可在不连接设备的环境中实现与验证；D阶段实测对照、E阶段实机搜索、F阶段物理验收仍需各自门槛通过。所有固件编译上机、数值配置及实机实验仍由用户在各门槛通过后分别执行/确认；软件交付不自动代表这些阶段验收完成。
